# PsychInterview — handoff

## 1. Project and audience
- **What:** PsychInterview, an offline iPad web app for psychiatry residents at Mariveles Mental Wellness and General Hospital (MMWGH). Residents enter interview data and export Word files, slides, and other clinical documents. Owner: Ma. Isabella P. Navarro, MD (GitHub `isaymotion`). She does not code, so explain steps plainly.
- **Repo:** `isaymotion/case-psychinterview` (public). `main` is live on GitHub Pages: https://isaymotion.github.io/case-psychinterview/
- **Branches:** `main` (the site), `dev-tools` (tools + this file; never merge into main). Old feature branches are already merged.
- **Files on main:** `index.html` (the whole app: config, Word writer/reader, UI, CSS in one file, ~3,700 lines), `slides.js` (PowerPoint generator, `CaseSlides`), `pdf.js` (PDF slides, `CasePDF`), `sw.js` (offline cache), `manifest.webmanifest`, `templates/` (5 slide designs + backgrounds), `fonts/`, icons, `tools/` (template builders).

## 2. Fixed rules
- App name is **PsychInterview** everywhere (renamed from "Case & MSE"). Internal ids like `case-mse-` cache prefix and `psyCaseApp.v1` storage key must NOT change (would lose saved data).
- Home-screen attribution: "Web app developed in 2026 by Isabella Navarro, MD. Latest version <date>. isaymotion@gmail.com". Update the date (`const VERSION=` in index.html) on each release. Formal documents: "Ma. Isabella P. Navarro".
- Hospital calls residents "first/second/third years", never "PGY".
- Never break old data: keep every existing field id; renamed labels go in `alias:[...]`; retired fields get `legacy:true` (shown only if filled). Old Word files must still import.
- No patient data in the repo (it is public). Tests use the fictional fixture only.
- Every release: bump `CACHE = PREFIX + 'vNN'` in sw.js and the VERSION date, **add a `CHANGELOG` entry at the top (next `id`, `v:'vNN'`) in index.html**, run tests, then publish. `t_home.py` fails if the newest What's new entry and the sw.js cache number disagree.
- **Publishing (her standing instruction, 2026-11-12):** "Always push direct to the repo from now on, you have full access." After tests pass, push straight to `main` (`git push origin HEAD:main`), no pull request and no asking first; then tell her what went live. If the session blocks the push or lacks write access, attach the repo (`add_repo`, access push); if still blocked, say so plainly and fall back to a PR (§8).
- User preference: use subagents for simpler tasks; Claude keeps design, clinical content decisions and final review.

## 3. Architecture and data formats
- **Record store:** `localStorage['psyCaseApp.v1'] = {cases:{id:{id,kind,created,updated,data,...}}, last:{...remembered settings}}`. Kinds: `case`, `pn` progress note, `dc` discharge summary, `mc` medical certificate, `ca` clinical abstract, `ho` handover, `sp` safety plan.
- **Home screen (v30):** `renderHome()` draws a dark top bar (`.bar.top`, buttons `.btn.ghost`: `#news` with unread `.badge`, `#imp`), then `.home-grid` = `section.start` (tiles built from `STARTS`; ids `#new #newpn #newdc #newho #newmc #newca #newsp` are unchanged) + `section.recs` (search `#q`, type chips `.fchip[data-k]`, cards `ul.cases li.k-<kind>` each holding `button.open[data-open]` and `button.rm[data-del]`). Layout: side column from 1000px wide, four-column tile grid below that, two columns on phones. Search/chips only toggle `hidden` on the cards (`homeQ`, `homeK` keep the choice for the session). Kind colours come from `.k-<kind>{--k:…}`; icons are inline SVG paths in `ICONS` via `ic(name)`.
- **Delete one record (v30):** `askDelete(id)` (confirm sheet) then `removeRec(id)`, which deletes, re-renders home and shows `toast(text,'Undo',fn)` for 15 s (8 s before v33, changed at her request; the record is held in memory only until then). The editor's Delete button also goes through `removeRec`. "Delete all records" keeps its plain `confirm`, then (since v32) shows the same Undo toast; undo merges the kept records back with anything created in the meantime.
- **What's new (v30):** `CHANGELOG` array in index.html (newest first; `{id, v, date:'YYYY-MM-DD', title, items:[[type,text]]}`, type `feature|update|fix` shown as New/Improved/Fixed), page `renderNews()`. Unread = entries with `id > store.last.newsSeen`; a device that has never opened the page sees only the newest as unread. Opening the page sets `store.last.newsSeen`. Entries before v24 carry no version number (cache numbers were not recorded then).
- **Theme and text size (v32):** `#aa` and `#theme` buttons in the dark top bar of the home and What's new screens (`lookButtons()` + `wireLook()`); the settings apply to every screen. Saved as `store.last.theme` (`'light'`, `'dark'`, anything else = match the device) and `store.last.textSize` (index into `SIZES`: Small .9, Normal 1, Large 1.12, Larger 1.25); `applyLook()` sets `data-theme` on `<html>` and `--tz`, and `body{zoom:var(--tz)}` scales everything (font sizes are in px, so there is no rem scale to change). Dark rules are still written once, as `@media (prefers-color-scheme:dark){ :root:not([data-theme="light"]) … }`; `forceDark()` copies them at start-up into `<style id="forcedDark">` for `:root[data-theme="dark"]`, so keep that exact selector form. Because zoom does not change media queries, anything sized in `vh` must divide by `var(--tz,1)` (rail, sheet, pick list do), and the top bars adapt with container queries (`.bar{container:bar/inline-size}`: see the v36 line below for the current thresholds).
- **Home list views (v34):** `store.last.homeView` (`'pt'` By patient, default; `'all'` flat) and `store.last.homeSort` (`HOME_SORTS`: edited, name, created). `homeGroups(list)` groups by normalised MRN (`recPt`), falling back to the name (`nameKey`); a patient with two or more documents gets one card with `+ Progress note` (`[data-newpn]`) and `Export all` (`[data-expall]`). `rec.exported` = time of the last Word export (set by `markExported(id)` on share, download or Google Docs); `expTag(rec)` shows "Exported …" or "Edited since export"; `isStale` = exported `CLEAN_DAYS` (7) or more days ago and not edited since, flagged with a "Ready to delete" chip and a `.tidy` banner. Typing an MRN that another case has shows a notice offering to open that case.
- **Backup / restore / Export all (v35):** card `.backup` under the list (`#bkSave`, `#bkOpen`, `#bkFile`). File `PsychInterview_Backup_<date>.json` = `{app:'psychinterview', kind:'backup', format:1, made, version, count, cases}` or, with a password, `enc:{alg:'AES-GCM', kdf:'PBKDF2-SHA256', iter, salt, iv, data}` instead of `cases` (base64). The backup holds records only, never `store.last` (so not the passcode). `backupOpen` merges: adds records not here, replaces only older copies, never deletes, Undo for 15 s; ids must match `^[\w-]{1,64}$` and the kind must be in `SCHEMAS` (ids are written into the page). `exportPatient(recs)` builds every Word file with `docxFor`, shares them together where the device can, otherwise one zip via `DocxGen.zip` (now exported from DocxGen). `store.last.backupAt` = last backup time.
- **Passcode lock (v36):** card `#lockCard` under Backup (`#lockSet`; when on `#lockNow`, `#lockChange`, `#lockOff`, `#lockIdle`). `store.last.lock = {salt, hash, idle}`: PBKDF2-SHA256 (120,000 rounds) of a 4 to 8 digit passcode, idle 1, 5 or 15 minutes. **It is a screen lock only; records in localStorage are not encrypted**, and the app's own wording says so: keep it that way. `showLock()` adds `div.lock` over the page and sets `inert` on everything else; at start-up the body is emptied first and `renderHome` waits in `whenUnlocked`, so no patient detail is in the page before the passcode. Five wrong tries = 30 s wait. "Forgot passcode?" can only erase all records and the lock (after a confirm). Idle lock: `lastActive` is updated on pointerdown/keydown/input; `idleCheck` runs every 10 s and when the app becomes visible. Needs `crypto.subtle` (https or localhost); without it the card is hidden and a saved lock is ignored.
- **Top bar inside a record (v36):** `header.bar.top.ed` (dark, white Export button) with one `#aa` button that opens the text size and theme sheet; `wireLook()` works with or without `#theme`. Container queries: `.x-long` label parts hide at 860, `.hide-sm` at 600, `.hide-xs` (the editor's Aa) at 480.
- **Place in the app, address and back (v39):** `rec.at` = id of the section last shown in a record; `store.last.lastOpen` = record last opened (home screen `#cont` Continue card). `openRec(id)` starts at `secAt(rec)`. The address is `#/r/<record id>/<section id>` or `#/news`, ids only, never a name: `syncURL(hash, push)` (opening a record or What's new pushes one history entry with state `{inApp:1}`; section changes replace), `goBack()` for the Records buttons, `route()` on `popstate` and at start-up when the address has a place (waits in `whenUnlocked`). Google's `#access_token=` return address is left alone. Every section change goes through `goSec(i, fieldId)`, which can scroll to a field and flash it.
- **Rail tools (v39):** `renderRail()` keeps `.rail-top` (`#find`, `#blanks`) and redraws only `#railList`. Find: `railQ`, `findHits(q)` over `plainText(f,d)` (typed text), field labels and section names; hits are `button.hit[data-hit][data-hf]`. Dots: `secState(s,d)` = `''`, `'part'` or `'full'` (classes `dot`, `on`, `full`); `countable(s,d)` leaves out sub-headings and unfilled `legacy` or `opt:true` fields. `blanksSheet()` lists empty sections and the blank fields of partly filled ones; the case Export sheet links to it (`#seeBlanks`). `docsSheet()` (tap `h1#title.tap`; not on handovers) lists the same patient's documents via `homeGroups` and has `#dsPn` (+ Progress note). `#title`'s first child must stay the name's text node (the name field updates it).
- **Word file without the name (v41):** case Export sheet has `[data-wm]` full / initials / alias. `docxFor(rec, layout, showAs)` runs `CaseSlides.deidentify` on a copy first, so text, genogram picture, file name and the embedded JSON all carry the replacement; such a copy does not call `markExported`; Google Docs gets it through `intent.showAs`. The slides have had the same choice ("Show the patient as") since before v24.
- **Backup reminder (v41):** `backupDue(list)`: records changed since `store.last.backupAt` and that backup (or, with none, the oldest record) is `BACKUP_DAYS` (14) old; banner `.tidy.bk#bkNudge` with `#bkNow` and `#bkLater` (`store.last.backupSnooze`, hidden `SNOOZE_DAYS` = 7). The clean-up banner is `.tidy:not(.bk)`.
- **Rating scales (v43):** `SCALE_PHQ9`, `SCALE_GAD7` (list `SCALES`), each a `radios` field with `scale:'<name>'`, `opt:true`, `bands`, optional `flag` (the item that needs a risk assessment when above 0), every item scored from `SCALE_OPTS` 0 to 3. In the case section `ros` and the progress note section `pnO`. Saved like any `radios` field: `d.phq9 = {"<item label>": "2", …}`, so the item labels are storage keys: never reword one. The labels are short paraphrases in the app's own words, not the questionnaire text; keep it that way, and add only scales that are free to reproduce (not the MMSE, MoCA forms and the like). `scaleScore(f,d)` gives `{n, of, total, max, done, band, flag}`; `scaleLine(f,d)` is the one-line text used by both Word layouts, the slides' notes and `prev` in `progressFromSource` ("Last documented"). Slides draw a `stats` tile. On screen: `.scalebox#sc-<id>` with `[data-clearscale]`.
- **Forms:** `SECTIONS` (case) and `PN_SECTIONS`, `DC_SECTIONS`, … registered in `SCHEMAS[kind] = {sections,title,name,file}`. Section: `{ id:'labs', num:'21', title:'…', note:'…', risk:true?, group?, fields:[…] }`.
- **Field types:** `text`, `area` (`quote`, `big`, `tool`), `checks` (`o:[…]`, `score`), `radio` (`o`, `detail` → value in `id+'__d'`), `radios`, `parts` (`p:[keys]` → object), `table` (`c:[cols]`, `rows`), `lines` (array of strings; `defaults:true` = references), `grid` (`rows`,`cols` → `{ "Row|Col": text }`), `family` (array of `{id,name,rel,age,sex?,status,psych,cond,withPt,desc}` plus, since v27, `occ` occupation/role, `count` several people in one symbol, `twin`, `of` id of the person they attach to, `relStatus` couple's relationship; see Genogram below), `labs` (`labPanels:{cbc:[[test,value,range],…], ua:"text"}`), `sub` (subheading).
  Example: `{t:'radio', id:'progRating', label:'Prognosis', o:['Good','Fair','Guarded','Poor']}`.
- **Case form order** follows the MMWGH Case Presentation Protocol: A encounter, B presentation details (title, prepared/supervised by, objectives), 1 Identifying data … 18A–18G MSE … 21 Labs, 22 Salient features, 23 Differentials (`ddx` table), 24 Working diagnosis (`primaryDx`), 25 Formulation (`bps` grid; a formulation builder was added later), 26 Risk, 27 Prognosis, 28 Goals & plan, 29 Discussion & references.
- **Word export:** `DocxGen.build(d, kind, ex)`. Case has two layouts: `ex.layout='protocol'` (hospital format, A4 Arial, letterhead from `PROTOCOL_HEAD` with base64 DOH + hospital logos) or `'form'` (labeled tables). Genogram PNG passed as `ex.geno`. Letters (mc, ca, ho, sp, and case files) embed the data as JSON in `docProps/custom.xml` (`CaseAppKind`, `CaseAppLayout`, `CaseAppPrint` fingerprint) so they reopen exactly; an edited file is detected by the fingerprint.
- **Footers:** three templates in index.html: `FOOTER` (form layout + all letters), `FOOTER_P` (protocol), `footerSP()` (safety plan). Page numbers use complex fields (`fldChar` begin/instrText/separate/end), each run carrying grey `sz` formatting, plus `<w:rPr>` in the paragraph's `pPr`. Do not go back to `w:fldSimple`: Google Docs drops its formatting (since v24).
- **Import:** `DocxImport.fileToData(file)` → `{kind, data, filled, missed, edited}`.
- **Genogram (rebuilt in v27):** `genogramLayout(d, opts)` returns `{prims, nodes, lines, w, h, left, linksLeft}` in units of one symbol width. `prims` is a plain drawing list (`line`, `poly`, `shape` with optional inner `text`, `text` label blocks) that includes the key; `genogramSVG(G, px)` and the slides `genogram` block both just loop over it, so a drawing change is made once in the layout. `opts.title` adds a heading (used by "Save genogram as a picture"); `opts.key:'right'` puts the key beside the tree (slides pick whichever is larger).
  - Extra data lives in plain keys on the case, outside the field system: `genoPtName`, `genoPtOcc`, `genoPtCond`, `genoPtFill` (patient card; fill defaults on), `genoByAge` (false = keep list order), `famLinks` = `[{a,b,type}]` where a/b are a member `id` or `'pt'` and type is one of `FAM_LINKS`. `famIds(d)` gives members permanent ids; links and `of` use ids, never list positions.
  - Roles (`FAMILY_RELS[].role`): father, mother, stepfa, stepmo, sib, phalf, mhalf, spouse, exsp, child, sibsp, nib, chsp, gchild, pgf/pgm/mgf/mgm, pside, mside, other (not drawn). `FAM_OF` says which roles ask "attached to whom". A person gets at most two partners drawn; half-siblings without a listed step-parent get a dashed "?" parent.
  - Layout: `unit()` (a person, partners, children, recursive) and `block()` (a sibship) place the patient's generation downward; parents, step-parents, aunts/uncles, grandparents are placed above. Text widths are estimated (`genoTextW`) so Node tests, Word and slides agree. Row height follows the tallest label. Half-sibling bars are lifted 0.22 above the full-sibling bar so they never touch.
  - Age order: `ageYears()` reads "33", "8 mo", "1 y 6 mo"; `famByAge` sorts oldest first and leaves unknown ages where they were listed; `famSorted(d)` is the "Sort list by generation and age" button.
  - Word: protocol layout prints the picture, the family profile sentences and a "Family relationships:" paragraph; form layout table gained an "Occupation / role" column (import reads the table by column heading, so old six-column files still open). Links, `of` and the patient card come back only through the embedded JSON, not from an edited file's table.
  - Slides/PDF: `ctx.shape({pts:[[x,y]…], close, fill, line, dash})` draws a free line (custGeom in pptx, path in pdf.js); `dash:'dot'` is dotted.
- **Slides:** `CASE_FORMAT` in slides.js sets order; `NOT_SLIDES = ['enc','pres']`. Text size (v25): `textScale` is the floor (`FS0`; app passes 1.3 Normal = 18 pt body, 1.6 Large = 22 pt). `paginate()` lays each section out at the floor, then enlarges it (to `FS_MAX` = 2.3, i.e. 32 pt body, since v26; three or four short facts may go two to a row via `wide`; a size is rejected as `tight` when a word is wider than its box) while the slide count stays the same, then lets each page grow on its own; `page.fs` is applied in `renderSlide` with `setFS`. Sizes must go through `z()` (reading text) or `zs()` (number tiles); MSE runs carry `u:` (unscaled size) and are rescaled by `atScale`. `colWidths` keeps columns at least as wide as their longest word.
- **Google export:** `GOOGLE_CLIENT_ID` in index.html (set). Redirect sign-in (no pop-up), scope `drive.file`, uploads to Drive folder "PsychInterview", converts to Google Docs/Slides. Google Cloud project is in "Testing" mode: only test users she lists can sign in.

## 4. Per-unit recipe (a feature or change)
1. `git checkout main && git pull` in the clone; branch `git checkout -b <topic>`.
2. Edit index.html / slides.js / pdf.js with small exact replacements (Python `str.replace` with `assert old in s`).
3. If adding a field type: update `isFilled`, `fieldHTML`, input/click handlers, Word export (`valueParas` or a table), import (`parseValue`/table detection), `extText` (plain text for notes/slides), and slides `sectionBlocks`.
4. Bump `CACHE` in sw.js and `VERSION` date.
5. Run tests (§5); look at rendered output images for any visual change.
6. Commit with attribution lines and push straight to `main` (§2 Publishing).

## 8. Pitfalls learned
- `gh pr create` fails (GraphQL blocked). Use REST: `gh api repos/isaymotion/case-psychinterview/pulls -f base=main -f head=<branch> -f title=… -f body=…` then `gh api -X PUT repos/…/pulls/<n>/merge -f merge_method=merge`.
- Repo write access must be attached to the session (`add_repo` with `access: push`; git proxy returns 403 otherwise). On 2026-11-12 self-merging a PR was blocked as "merge without review" until she said "yes, merge it" each time; she has since given the standing instruction in §2. Do not try other routes around a block.
- Push with `git push -u origin <branch>`; the stop hook complains about branches without upstream. Clone is shallow with a single-branch refspec: run `git config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'` once.
- Pages build status API is blocked; just tell the user to wait 1–2 min and reopen the app.
- docx schema order: `<w:jc>` comes after the other pPr items she uses; `<w:rPr>` (paragraph-mark formatting) goes after `<w:jc>`. Validate after any docx change.
- Google Docs ignores formatting on runs inside `w:fldSimple`; use complex fields.
- When judging slide text size, read `sz=` values from the pptx XML; small contact-sheet thumbnails are misleading.
- Hidden rail in portrait: test scripts must use `textContent`, not `innerText`.
- Playwright: start the local server inside the test (`serve.py`), not with `&` in bash (gets killed).
- Lab cards need `minmax(400px,…)` or names truncate in portrait.
- Working diagnosis is excluded from "Rule out" lists (`caseDifferential`).
- The official Stanley-Brown safety plan wording is copyrighted: keep original six-step wording with the credit line; don't reproduce the official form.
- Other sessions edit main too: always `git pull` first. `/tmp/work/release.sh` style helper (commit, fetch, refuse to push if main moved, then push main and dev-tools) is worth recreating.
- This session's own context was cut mid-task once (v34 was live and v35 sat uncommitted in the clone with no memory of it). At the start of any turn, run `git status` and `git log -3` in the clone before planning, and commit or release finished passes promptly.
- Buttons that open a file picker (`#bkOpen`) attach their `onchange` on click, so tests must use `expect_file_chooser`, not `set_input_files`.
- Idle-time behaviour is tested with `page.clock.install()` before `goto`, then `clock.fast_forward('05:30')`.
- The app saves the open record when a page closes (`pagehide`), so a test that swaps `localStorage` and reloads gets overwritten: open a fresh page first (see `t_family.py`).
- Genogram labels: never let a line to children pass through a label. Couples are spaced by `apart()` (twice the wider label) and `dropX()` is the safety net; cross-generation relationship lines start under the upper person's label.
- Rebasing onto another chat's release always conflicts in `CHANGELOG` (both add an entry at the top) and sometimes `sw.js`: keep both entries, give yours the next id and cache number.
- After the Genogram chat pushes its repo and before it pushes PsychInterview, `sync_engine.py --check` says DIFFERENT for a few minutes. Do not copy the block yourself; fetch PsychInterview again.
- A home-screen address with a place in it reopens that place: tests that need the home screen should `goto` the bare URL and reload.
- `t_oldfields.py` needs four arguments (not run by `run_all.sh`); check its header before using it.
